# 飞书项目度量公式

将业务场景转换为**可直接粘贴到飞书项目度量图表**的公式，或将既有公式解析成紧凑、可评审的业务 DSL。

## 目标

每次输出必须同时满足：

1. **可用公式**：只用已确认存在的字段和飞书项目公式函数；不定义变量、不新增/猜测基础字段。
2. **可读语义**：让用户不用阅读嵌套 `IF` 就能理解样本、分子/分母、阈值、边界和得分。
3. **逻辑唯一**：同一子分只出现一次；新旧公式不能同时叠加；结果不含重复的守卫或死分支。

## 权威输入

读取 `references/verified-rdhs-vocabulary.md` 后再生成或审阅公式；处理 RDHS 组件、长分支或历史公式时，再读取 `references/rdhs-semantic-examples.md`。

优先级从高到低：

1. 用户本轮明确确认的字段、状态、终点、阈值、得分范围；
2. 用户贴出的已运行飞书项目公式；
3. `references/verified-rdhs-vocabulary.md` 中的确认词汇；
4. 不足之处：明确提问，**不要补造字段或状态名**。

历史对话中的助手建议不是事实来源。若它与用户最新确认冲突，以用户最新确认覆盖。

## 绝不做的事

- 不生成 `K = ...`、`R = ...`、`变量 = ...` 等飞书项目度量公式不支持的变量定义。
- 不把语义 DSL 中的别名原样带进最终公式；最终公式必须内联所有表达式。
- 不新增“首次进入开发时间”“有效样本标记”等工作项基础字段，除非用户明确要求创建字段。
- 不擅自给样本加 `提出时间非空`、时间先后关系、状态排除等数据质量条件。用户若指定“仅完成时间非空”，就只使用该条件。
- 不把旧版子分和新版子分相加；同一 RDHS 组件只保留一条当前生效路径。
- 不执行 chart 创建、更新、保存或代码改动，除非用户明确要求。

## 工作流 A：业务场景 → 度量公式

### 1. 固化口径

先从用户场景或已有公式提取：指标目标、样本、输入子项、边界和得分范围。仅在缺少会改变结果的关键信息时提问；不要用数据质量假设补齐。

### 2. 先出“业务评审版”

读取 `references/presentation-pattern.md`，按其中的**得分指标标准结构**呈现；RDHS/长公式场景同时参考 `references/rdhs-semantic-examples.md` 的分支映射和组合解读。核心顺序固定为：

```text
业务目标 → PlainText 计算口径 → 输入说明 → 得分规则 → 分档 → 补充业务解读 → 可复制公式
```

- 用 `A`、`B`、`C` 等短别名压缩重复表达式，让用户先理解逻辑。
- 别名只允许存在于 `PlainText` 代码块、分档表和业务解读；最终飞书公式必须完整内联。
- `补充说明`至少覆盖：守卫/无样本含义、一个健康组合、一个需治理组合。不要只输出技术自检。
- 非得分指标使用该参考中的简化结构，不强造分档表。

### 3. 再出“可复制版”

- 使用用户确认的原始字段名，例如 `${完成时间(秒)}`，不能改写成口头别名。
- 只用已验证函数：`IF`、`ISNULL`、`AVGIF`、`COUNTDISTINCTIF`、`FILTER`、`MAX`、`MIN`、`TODAY`、`AVG`。
- 公式外不声明变量；同一表达式需要多次判断时直接完整展开。
- 除法先有零分母守卫。
- 若终点已统一为 `${完成时间(秒)}`，同一新公式中不得残留 `${验收完成时间}`。
- 得分组件显式标注范围，如 `完成节奏子分 0~12`、`WIP 子分 0~8`，并验证总和不超过组件满分。

### 4. 生成后自检

最终回复前逐项检查：

```text
[ ] 只出现用户确认的字段、状态、函数
[ ] 无变量定义、伪代码或未展开别名
[ ] 括号、IF 三元参数、分子分母配对完整
[ ] 零分母有前置 IF
[ ] 一个当前组件只出现一次；无旧版 + 新版双加
[ ] 子分范围之和 <= 组件满分；RDHS 仍可保持五组件和=100
[ ] 语义版与公式版样本集、阈值、边界一致
```

若用户给出真实 chart raw 或 CLI 返回，优先按实际行值检查分档范围、`RDHS==组件和` 和新旧交叉影响；不要只凭公式肉眼断言。

## 工作流 B：公式 → 业务 DSL

公式解析时，不要逐行复述。读取 `references/presentation-pattern.md`；RDHS/长公式再读取 `references/rdhs-semantic-examples.md`，将公式反推为同一套“业务评审版”：

1. 先用 PlainText 定义 A/B/C（真实分子、分母、时间段或子分）；
2. 用“得分规则”和分档表还原嵌套 `IF`；
3. 用“补充说明”解释组合的业务含义；
4. 最后才列出逻辑风险和最小修正建议。

必须明确：

- 实际样本集、分母、守卫、排除项；
- 分档的完整闭开边界；
- 重复子表达式在最终公式中虽内联、业务上只是一项；
- 重复子分、样本不一致、旧新字段混用、范围越界、分母稀释、无样本送分等风险。

## RDHS 特别规则

RDHS 固定结构：

```text
RDHS(100') = 链路闭环(25') + 交付闭环(15') + 时效节奏(20') + 颗粒度对齐(20') + 质量敏锐度(20')
```

审阅 RDHS 时额外检查：

1. 每个组件恰好一次；
2. 时效组件在 `0~20`；
3. 若拆为完成节奏与 WIP，必须是 `0~12 + 0~8`，不得将完整时效公式再加 WIP 子分；
4. 结束时间统一采用用户确认的 `${完成时间(秒)}` 时，旧 `${验收完成时间}` 不得残留；
5. 产品业务合格规则（如 `RDHS>=70 && 完成样本>=10`）是治理资格，不得悄悄污染 chart 原始分，除非用户明确要求。

## 输出约定

默认顺序遵循 `references/presentation-pattern.md`：

```text
指标名称与业务目标
→ PlainText 计算口径（A/B/C）
→ 输入说明
→ 得分规则
→ 分档
→ 补充业务解读
→ 飞书项目可复制公式
→ 公式自检
```

用户若只要公式，仍输出“计算口径 + 边界 + 得分范围”后再给公式；用户若只要解析，不输出新公式，避免擅自改逻辑。

## 验证场景

见 `evals/evals.json`。对真实公式生成任务，以用户确认的字段为准，不把 eval 中的字段扩展成通用字段。
