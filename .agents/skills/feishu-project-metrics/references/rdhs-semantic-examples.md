# RDHS 语义表达示例

本文件吸收 archived `daily-data-ops` 旧技能的表达方式。示例用于说明如何把巨型飞书公式讲给业务方，**不是当前生效公式的事实来源**。当前字段、终点、阈值和得分以用户最新确认及 `verified-rdhs-vocabulary.md` 为准。

## 推荐呈现顺序

```text
业务目标
→ 关键输入（PlainText 别名）
→ 分支决策
→ 分档表
→ 业务组合解读
→ 完整可复制公式
```

PlainText 别名只用于阅读：

```text
A = 需求侧指标
B = 缺陷侧指标
N = 样本/参与人数
```

最终飞书公式不得出现 `A`、`B`、`N` 定义，必须展开真实字段表达式。

## 链路闭环语义示例

### 业务目标

衡量项目是否形成**需求驱动的研发闭环**；缺陷关闭是补充信号。只有缺陷关闭、没有需求吞吐，不视为完整链路闭环。

### 关键输入

```text
N = 有效参与人数
A = 月人均需求吞吐量
B = 月人均缺陷关闭量
```

其中：

- `N`：按实际公式的参与人、角色和工作项类型口径去重；不要根据名称自行扩展角色。
- `A`：已完成产品需求数 ÷ 统计月数 ÷ 有效参与人数。
- `B`：已关闭缺陷数 ÷ 统计月数 ÷ 有效参与人数。
- `A/B/N` 是解释别名，不是飞书度量变量。

### 分支决策

```text
N = 0
→ 链路闭环得分 = 0

N > 0 且 A > 0
→ 需求侧得分 + 缺陷侧得分

N > 0 且 A = 0
→ 缺陷单边兜底分，不能按完整链路给分
```

### 需求侧分档示例

| A 条件 | 需求侧得分 | 业务含义 |
| --- | ---: | --- |
| `A ≥ 0.8` | 15 | 需求入口活跃、吞吐稳定 |
| `0.5 ≤ A < 0.8` | 12 | 需求入口基本稳定 |
| `0.2 ≤ A < 0.5` | 8 | 需求入口偏弱 |
| `0 < A < 0.2` | 4 | 需求入口低活跃 |
| `A = 0` | 0 | 需求入口断流 |

### 缺陷侧分档示例

| B 条件 | 缺陷侧原始得分 | 业务含义 |
| --- | ---: | --- |
| `B ≥ 3` | 10 | 缺陷闭环充分 |
| `1.5 ≤ B < 3` | 8 | 缺陷闭环稳定 |
| `0.5 ≤ B < 1.5` | 5 | 缺陷闭环一般 |
| `0 < B < 0.5` | 2 | 缺陷闭环偏弱 |
| `B = 0` | 0 | 缺陷闭环缺失 |

### 组合解读

| 组合 | 业务含义 |
| --- | --- |
| A 高、B 高 | 需求与缺陷两侧流动稳定，链路整体健康 |
| A 低、B 高 | 缺陷治理活跃，但需求吞吐不足；可能处于存量缺陷治理期或需求入口不足 |
| A 高、B 低 | 需求吞吐正常，但质量闭环偏弱；需关注缺陷暴露或关闭及时性 |
| A = 0、B > 0 | 仅有缺陷侧活动，不视为完整需求驱动闭环；按当前公式的单边兜底规则处理 |
| N = 0 | 参与角色数据缺失或没有有效活动；先检查参与角色与角色人员维护 |

## 公式→语义的分支映射模板

审阅任意复杂公式时，使用以下表格而不是逐行解释：

| 原公式结构 | 语义 | 核查点 |
| --- | --- | --- |
| 最外层 `IF(N == 0, 0, ...)` | 无有效活动，直接不给分 | N 的样本范围是否正确 |
| `IF(A > 0, 完整评分, 单边评分)` | 有需求吞吐与无需求吞吐走不同路径 | 单边分是否被误算为完整分 |
| 连续 `IF(A >= ..., score, ...)` | 按需求侧活跃度分档 | 区间边界是否重叠/遗漏 |
| 连续 `IF(B >= ..., score, ...)` | 按缺陷侧闭环能力分档 | B=0 与 B>0 是否区分 |
| `+` 连接两个完整评分块 | 子分相加 | 是否误把同一子分重复连接 |
| `TODAY()` | 未完成项的实时年龄 | 是否应属于 WIP 指标，而非已完成周期 |

## 评分公式审查重点

- 先确认组件总分上限，再检查每个分支的最大值。
- 看到相同的 `COUNTDISTINCTIF/FILTER` 多次出现，不直接判定重复；先判断它们是否只是同一业务输入的内联展开。
- 看到两个完整得分树以 `+` 相连，检查它们是否属于不同子项；旧版与新版同一子项不得同时相加。
- `A/B` 只在语义层定义；复制版必须使用真实字段。
- 样本不足、无活动、无在途等边界必须说明业务含义，不能用未确认的“中性分”补齐。
- 任何字段、状态、函数不在用户确认范围内时，标记待确认，不自行生成。
