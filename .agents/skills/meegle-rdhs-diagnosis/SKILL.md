# RDHS 诊断与历史过程查询

## 1. 先选最小路径

| 用户目标 | 必需数据 | 命令 / 停止条件 |
|---|---|---|
| 指定历史整月的 BG/业务线过程情况 | 对应月度趋势；业务线仅另查业务线树 | `--month YYYY-MM`，核心结果与限制复核后即交付，不自动补产品榜单或近6月趋势 |
| 当前产品/业务线/BG RDHS | 本月产品图 + 主数据；只解析展示产品的责任人 | `--product` / `--business-line` / `--all`；保留原产品详细诊断及完整健康度榜单 |
| 对比 | 历史过程同一趋势源中上一个自然月；当前RDHS另查上月图 | 仅用户要求时加 `--compare`，缺基线不可用最近有数据月份替代 |
| 最近趋势 | 对应近6个完整月趋势 | 仅用户要求时加 `--trend`，不与 `--month` 同用 |
| 指标解释 | 本地权威公式及解释 | 读 references/3-metrics-explainer.md 与其引用公式，不默认线上取数 |

必须用 `scripts/rdhs_query.py`，不要多轮手写抓取/重复解析。脚本目录相对本 SKILL.md。年份含糊时先确认；不要将本月 MTD 当成整月。

```bash
python3 <skill-dir>/scripts/rdhs_query.py --all --month 2026-09
python3 <skill-dir>/scripts/rdhs_query.py --business-line "录音笔" --month 2026-09 --compare
python3 <skill-dir>/scripts/rdhs_query.py --product "产品名称" --compare
python3 <skill-dir>/scripts/rdhs_query.py --all
python3 <skill-dir>/scripts/rdhs_query.py --business-line "业务线名称" --trend
```

历史可查深度受趋势源保留范围限制，不只限近6月展示窗口。指定月不存在则返回未获取；不支持历史单品评分，没有可靠历史主数据快照不能用当前状态冒充月末状态。

## 2. 数据与缓存契约

空间：`cbg_product_develop`；产品主数据类型：`693f665435b354b7ca0085dc`。

| 数据源 | Chart ID | 期间依据 |
|---|---|---|
| 本月产品 RDHS | `7659618575337915254` | 图表“本月”角色 + 查询时 UTC+08:00，MTD |
| 上月产品 RDHS | `7681204196376314742` | 图表“上月”角色 + 查询时 UTC+08:00，已收口自然月 |
| BG 月度过程 | `7688169549312557942` | 图表自身 `YYYY-MM` 维度 |
| 一级业务线月度过程 | `7688177041702650742` | 月份 + 一级业务线维度 |
| 二级业务线月度过程 | `7688220298042147702` | 月份 + 两级业务线维度 |

chart_id 不是固定月份。相对图缓存按空间、图表与有效月份隔离；取数跨月拒绝结果以防错标。相对期间仍依赖图表配置正确性，不宣称客户端日期验证了服务端筛选。`queried_at` 是请求时间，缓存可能更早获取。

- 本月默认实时（TTL=0）；`--cache-ttl N` 可显式允许短缓存。
- 上月、趋势和主数据默认短缓存30分钟，业务线树1小时；历史可回填，并非永久不可变。
- 只有明确需要重拉时用 `--refresh`；不要默认穿透全部缓存，也不读仓库 runtime/data 静态快照代替线上源。
- 主数据分页单页上限200，分页未完成必须报错。指标按 quota_titles 名称动态解析。
- `is_zero_spec=true` 是占位，不计有效样本；真实0分仍是有效P0。缺列/非法值/NaN/Infinity/分数越界/五维不一致明确报错，不补0。五维总分允许0.05分显示舍入容差，不改原分。
- 重名、业务线不一致、多块响应等未知结构停止并明确原因，不能静默覆盖、跨线配分或截断。

## 3. 纳管与分档（唯一权威规则）

当前上层RDHS只纳入 `In Progress`、明确标准产品、非测试业务线。交付定制枚举 `hmeckpgbh` 排除；标准枚举 `ettrf_vl8`；未知属性不默认当标准产品。

整体展示**已度量产品RDHS算术平均 + 样本数/覆盖率**；不新增复合分。未返回行不等于业务未度量，需区别图表范围、身份匹配、占位与真实缺测。范围未确认时不作全BG整体分档；不能用月度趋势反推RDHS。

| 有效RDHS | 分档 |
|---|---|
| <45 | 重点治理 P0 |
| 45~<60 | 风险改进 P1 |
| 60~<70 | 持续优化 P2 |
| ≥70 | 达标 / 常规跟踪 |

无有效匹配单列“未度量 / 数据治理（原因待核实）”，不混入均值或P0；详情完整保留在当前健康度榜单，历史过程回答不强塞产品目录。

## 4. 诊断必须区分事实与假设

保留7阶规则优先级：参与人数0 → 吞吐0或链路分<15 → 积压>30% → 严重缺陷>15% → 发布分<8 → 时效分<10 → 其他分项优化。非积压主因但积压>30%时追加积压事实。

- 正吞吐但链路分低不可写成吞吐0；零吞吐只代表完成记录未出现，不能证明团队没工作。
- 零参与不直接证明角色缺失；低时效分须拆查开发/交付周期比值及积压，不能直接证明绝对周期长。
- 周期比较两月均须有需求完成和有效周期样本；缺陷质量须独立核实缺陷分母，不能用需求样本代替。
- 严重/低级缺陷比例变化不直接等于治理效果；未知分母不作因果判断。
- 建议对应五维短板与责任角色；不承诺满分或达标，不为提分鼓励虚假结项。

五维状态按实际/满分：≥80%正常，50%~<80%偏低，<50%严重偏低。公式不在诊断层重算改分；权威来源见 references/3-metrics-explainer.md。

## 5. 执行边界与失败处理

**CHECKPOINT · 只读**：不自动流转、关闭、终止或删除线上工作项；实施建议须负责人确认和真实验收凭证。

**CHECKPOINT · 范围异常即收口**：已确认结果先交付；一句话列出缺失范围，不自动长链路补查、反复读参考或生成额外文件。业务线明细/整改任务只有用户要求才下钻。

- 频控/可识别临时网络错误：串行线性退避，最多3次；单CLI请求30秒超时。认证、权限、参数或响应契约错误不盲重试。
- `AUTH_REQUIRED`：提示用户 `meegle auth login`，不能降级旧快照。
- 姓名解析失败：保留用户标识并警告，不声称已核实名字。
- JSON空结果保留结构；局部基线/范围失败标记partial和warnings。
- 严禁并发冲击Meegle接口，不新增线程池。耗时按源请求数与冷热缓存评估，没有基准不承诺2秒/5秒；取数及复核都计入预计时间。

## 6. 输出与验收

历史过程：目标月 → 核心产出/时效/质量 → 可比上月（若要求） → 治理建议与限制。过程表现、建议与已实施措施分开；措施实施需要另查任务/纪要，不凭度量猜测。

当前健康度：整体摘要与覆盖 → 当前治理切口（每类最多2款） → 用户要求的趋势 → 完整产品榜单；精确单品保留五维、7阶事实、真实角色与具体动作；模糊命中多款只列候选。

独立复核月份、关键比例/环比/分档计数；人数去重、比例和周期不直接加总或取业务线均值替代BG。全量过程趋势与自研产品纳管分母不同，不强制对账。
