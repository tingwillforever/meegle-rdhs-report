# 阶段三：指标解释与业务人话指南 (Metrics Explainer)

本文件是 RDHS 衍生度量公式（`docs/rdhs-base-indicator-formulas.md`）的解释层；公式不变，业务原因仅作待核实假设，不能从得分直接证明行为。有效度量及纳管遵循 SKILL.md。

## 一、 两层衍生计算全景

```text
【底层原料：11 项日常流水指标】
  1.有效参与人数  2.月人均需求吞吐  3.月人均缺陷关闭  4.需求交付周期     │
  5.需求开发周期  6.严重缺陷占比    7.低级缺陷占比    8.应发布需求数     │
  9.有效发布需求数 10.需求总量      11.积压需求占比                      │
       ↓（通过比值、阈值阶梯、分段加权加工）
【衍生能力：五大组件得分（满分 100'）】
  ① 链路闭环(25') ＋ ② 交付闭环(15') ＋ ③ 时效节奏(20') ＋ ④ 颗粒度对齐(20') ＋ ⑤ 质量敏锐度(20')
       ↓（相加）
【顶层结果：RDHS 综合得分】──> 四级治理分档 (重点 / 风险 / 优化 / 常规)
```

## 二、 五大衍生组件白话手册与提分秘籍

### 1. 链路闭环得分（满分 25'）
- **底层加工算法**：
  - 数据原料：有效参与人数、人均需求吞吐量（$a$）、人均缺陷关闭量（$b$）；
  - 前置门槛：参与人数 == 0 $\rightarrow$ 0分；
  - 需求侧（0~15分）：$a \ge 0.8 \rightarrow 15$分；$a \ge 0.5 \rightarrow 12$分；$a \ge 0.2 \rightarrow 8$分；$a > 0 \rightarrow 4$分；$a == 0 \rightarrow 0$分；
  - 缺陷侧（0~10分）：$b \ge 3.0 \rightarrow 10$分；$b \ge 1.5 \rightarrow 8$分；$b \ge 0.5 \rightarrow 5$分；$b > 0 \rightarrow 2$分；
  - ⚠️ **断链惩罚**：当月需求吞吐为 0 时，缺陷侧最高**封顶降为 5 分**（总分最多 5 分）。
- **业务大白话**：“测的是**团队是不是真在交付需求**。没有需求完成记录时链路分受限；需核实真实阶段与验收登记，不能直接证明只修Bug或没有交付。”
- **提分秘籍**：需求上线后及时在飞书项目中流转至“已完成/已验收”；Bug 修完点“已关闭”；卡片如实挂责任人。

---

### 2. 交付闭环得分（满分 15'）
- **底层加工算法**：
  - 数据原料：应发布需求数、有效发布需求数；
  - 计算闭环率 $p = \text{有效发布数} \div \text{应发布数}$；
  - 应发布为 0 时保底给 8 分；$p \ge 90\% \rightarrow 15$分（满分）；$p \ge 70\% \rightarrow 12$分；$p \ge 50\% \rightarrow 8$分；$p > 0 \rightarrow 5$分；$p == 0 \rightarrow 0$分。
- **业务大白话**：“测的是**需求上线有没有正规绑定发布计划**。应发布需求未有效关联发布计划会降低闭环率；实际得分按比例与样本计算，不必然全扣光。”
- **提分秘籍**：发版必建【发布计划】关联当期需求，发版完成在发布计划中确认结项。

---

### 3. 时效节奏合理性（满分 20'）
- **底层加工算法**：
  - 子项 A（已完成节奏，0~12分）：计算 $R = \text{开发周期} \div \text{交付周期}$。健康区间 $R \in [0.4, 0.7] \rightarrow 12$分；偏离逐步扣分。
  - 子项 B（在途积压，0~8分）：积压率 $\le 10\% \rightarrow 8$分；积压越深分值越低（6/4/2/0分）。总分 = A + B。
- **业务大白话**：“测两件事：**需求做起来拖不拖** ＋ **手上陈年积压多不多**。”
- **提分秘籍**：需求提出后尽快完成评审排期进入就绪；月末清退滞留超 60 天不做的僵尸需求。

---

### 4. 颗粒度对齐度（满分 20'）
- **底层加工算法**：
  - 计算配比值 $r = \text{缺陷关闭量} \div \text{需求吞吐量}$（平均完成 1 个需求报出并修复了几个 Bug）；
  - 黄金区间：$r \in [5, 40] \rightarrow 20$分满分；$r \in [2, 5)$ 或 $(40, 60] \rightarrow 15$分；$r == 0$ 或 $r > 80 \rightarrow 0$分。
- **业务大白话**：“测的是**需求拆得合不合身**以及**测试有没有测透**。高缺陷/需求配比或零缺陷是核查信号，需结合需求规模、样本和测试记录；不能直接证明拆分过粗或测试放水。”
- **提分秘籍**：大功能按用户故事拆细为 1~2 人周卡片；测试人员在需求提测阶段规范录入缺陷并闭环。

---

### 5. 质量敏锐度（满分 20'）
- **底层加工算法**：
  - 缺陷总数 == 0 $\rightarrow$ 5分；缺陷总数 < 10 $\rightarrow$ 10分；
  - 缺陷总数 $\ge 10$ 且严重缺陷占比 $\le 10\%$ 且低级缺陷占比 $\le 10\% \rightarrow 20$分满分；严重/低级占比超标则降档（15/10/5分）。
- **业务大白话**：“测的是**缺陷健康度**。不仅要有缺陷记录，而且致命严重 Bug 占比不能超 10%，低级界面 Bug 占比也不能超 10%。”
- **提分秘籍**：研发提测前做好自测和冒烟自检（压降低级缺陷）；架构设计加强评审（杜绝主链路严重缺陷）。
