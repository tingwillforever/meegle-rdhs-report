# 一级业务线 CTO 工作台

## 范围

复用 BG 大盘 → 业务明细工作台 → 产品详情的现有动线，不增加独立路由或重复月报。业务线链接：`?period=YYYY-MM&view=workbench&line=业务线全名`。只有 `line` 时也进入工作台。分享链接只分享月份、视图、一级业务线，不包含临时列表过滤器。

## 度量契约

- BG、一级业务线、二级业务线及月度趋势的 RDHS 均分都按产品等权计算：已度量得分总和 / 全部快照纳管产品数。未度量原值保留 null，仅考核均分计算按 0；空范围显示无数据。
- 分档：<45 重点治理；45~<60 风险改进；60~<70 持续优化；>=70 常规跟踪。未度量单列计数，并纳入治理敞口。待治理(<70)不等于 P0。
- 排名按未舍入均分降序，并列采用 1、1、3；差值先用未舍入数字计算，再四舍五入到一位小数。
- 环比只对比上一个自然月，缺月不使用最近历史月代替。展示两期产品数与新增/移出提示；MTD 与上月完整月不可直接归因效能升降。
- 工作台顶部整线指标与 BG 排名不受搜索、分档、二级业务线、分页影响。缺失二级归属归入“未分二级业务线”。
- 治理推荐最多 3 项，仅选择未度量或低于70分产品。显示指标事实与条件式核查动作，不据低分直接认定未开展研发或要求虚假结项。责任角色未在快照提供时明确缺失，不猜测。业务线人数/周期/缺陷比例不由产品简单平均拼凑。

## 验证与发布

```sh
npm test
npm run lint
npx tsc --noEmit --incremental false
RDHS_BASE_PATH=/meegle-rdhs-report npm run build:pages
# 真实Chrome + Python Playwright；先将 dist/static 映射至测试URL。
RDHS_E2E_URL=http://127.0.0.1:8089/meegle-rdhs-report/ python3 scripts/browser-acceptance.py
```

浏览器验收覆盖 BG→业务线→二级线→详情→治理产品定位→返回BG、分享、刷新、浏览器前进/后退、月份切换、无效业务线/缺月、桌面与手机，并断言无JS错误和HTTP资源错误。`RDHS_E2E_EVIDENCE` 可指定独立证据目录。

推送 `github/main` 后由 `.github/workflows/deploy-pages.yml` 自动构建发布。线上应对同一提交重新执行上述浏览器脚本；仅 Actions 成功或 HTTP200 不是完整验收。

## 本轮修正记录

- 问题：URL参数缺省时历史导航残留旧业务线；原因：仅处理存在的参数且 effect 依赖每次重建数组；修复：稳定快照引用并完整恢复参数默认值；验证：浏览器从无参数BG链接往返业务线。
- 问题：治理推荐定位产品与列表分页范围不同；修复：定位时清空临时列表过滤，按一致列表计算页码；验证：二级线/搜索后定位产品。
- 问题：健康产品被补位为P2治理；修复：只推荐未度量及低于70分产品；验证：健康列表返回空推荐单测。
- 问题：本地静态测试正常不能保证Pages资源正常，旧font缓存包含本机绝对路径；修复：导出字体URL为静态资源路径，并把嵌套`_next`复制至Pages产物根目录；验证：模拟Pages前缀剥离的服务与真实线上浏览器均检查资源HTTP错误。
- 问题：两条旧Pages工作流同时响应push且共享并发组，旧Python同步包装器测试未隔离部署动作，在CI实际尝试克隆/发布；影响：重复部署及测试依赖本机Git身份。修复：只保留main发布工作流，另一条改为PR只读校验；包装器单测显式`RDHS_NO_DEPLOY=1`，main发布前跑完整测试/类型/lint。验证：本地隔离测试与GitHub干净runner重跑。

## 限制

页面基于仓库中的月度快照，不是打开即直连飞书查询；代码发布不等于重新抓取业务数据。数据更新时间以快照为准。当前快照不包含产品责任人字段，不新增任务派发或任何线上工作项写入。
