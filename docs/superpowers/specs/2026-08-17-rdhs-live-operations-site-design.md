# RDHS 实时运营报告网页设计

## 目标

建设一个可持续运行的 RDHS 运营报告网页。数据由内网或本机同步器通过 Meegle CLI 获取并完成既有治理加工，站点负责校验后的快照接收、历史查询、趋势分析和业务线/产品下钻。

## 架构

系统分成两个边界清晰的部分：

1. `scripts/sync-rdhs-snapshot.py` 运行在能够访问 Meegle CLI 的本机或内网任务机。它调用现有 `run_periodic_report.py` 生成月度快照，读取 `report_data.json` 与 `audit_manifest.json`，转换成稳定的站点快照合同，并推送到站点写入接口。
2. Sites 托管 React/Vinext 应用。D1 保存结构化历史快照，服务端接口负责接收、验证、查询和聚合；浏览器只读取报告数据，不持有 Meegle 或同步密钥。

同步采用两阶段发布：快照必须通过源端覆盖率保护和站点端合同校验，D1 事务写入成功后才成为该周期的当前版本。失败刷新只记录诊断，不覆盖最近一次有效报告。

## 数据口径

- 产品底表：状态为 `In Progress` 的产品主数据。
- 排除范围：`测试业务线`，以及产品属性为 `交付定制` 的产品主数据。
- 关联键：规范化后的 `一级业务线 + 产品`，以产品主数据左关联 RDHS Chart。
- 未度量/待关联：RDHS 保持空值，不补 0，纳入重点治理和 P0。
- 治理分档：重点治理 `<45 + 未度量/待关联`；风险改进 `45~<60`；持续优化 `60~<70`；常规跟踪 `>=70`。
- 平均 RDHS：仅对已度量产品做等权平均，并同时展示样本数。
- 度量覆盖率：`已度量研发中产品数 / 研发中产品总数`。
- 五项趋势：对有效产品分别计算链路闭环、交付闭环、时效节奏、颗粒度和质量敏锐度的平均得分；不跨不同满分直接求和。
- 月度趋势只读取 `monthly` 快照；站点不提供周报切换。

## 快照合同

每份上传快照包含：

- `schemaVersion`：固定为 `1`。
- `cadence`：固定为 `monthly`。
- `periodKey`：月报为 `YYYY-MM`。
- `asOf`、`fetchedAt`、源图表 ID 与哈希。
- BG 总览、业务线分档、全量研发中产品、治理清单和数据审计。
- 源端接受行数、零分过滤量、空维度过滤量、研发中产品数、已度量数、未度量数、排除测试业务线数量和排除交付定制数量。

站点拒绝未知版本、非法周期、重复业务线/产品键、分档合计不等于产品总数、已度量数大于产品总数、产品分档与 RDHS 不一致以及覆盖率异常下降的快照。

## 存储

D1 使用三张主表：

- `snapshots`：周期、版本、状态、汇总指标、源哈希、抓取时间和诊断信息。
- `business_line_metrics`：每个快照的业务线产品数、四档数量、平均 RDHS、覆盖率和五项均值。
- `product_metrics`：每个快照的产品状态、RDHS、治理分档、优先级、五项分数、问题和行动。

常用查询按 `(cadence, period_key, is_current)`、`snapshot_id + business_line` 和 `snapshot_id + governance_band` 建索引。已有 `report_data.json` 可通过同一合同导入，作为趋势起点。

## 页面

单页工作台包含：

1. 顶栏：月份选择、最后更新时间、数据状态和更新数据按钮。
2. 总体判断：一句结论与当期关注重点。
3. 指标条：研发中产品、平均 RDHS、度量覆盖率、产品规范率和待治理占比。
4. 趋势区：月度平均 RDHS 折线、70 分基准线、覆盖率走势、四档堆叠分布和五项过程指标趋势。
5. 业务线总览：可排序表格，支持点击业务线进入下钻。
6. 产品下钻：搜索、治理分档筛选、未度量筛选，展示 RDHS、最低分项、主要问题与建议动作。
7. 数据说明：源图表、过滤量、关联情况、快照版本和最近失败原因。

桌面端使用紧凑的横向比较布局；移动端将指标条改为两列，趋势横向可滚动，业务线和产品使用可展开行。所有交互支持键盘焦点和触摸操作。

## 视觉方向

页面是安静、克制的运营工作台。基础色为白色 `#F7F8FA`、纸面白 `#FFFFFF`、炭黑 `#17201D`、次级灰 `#66716D`；治理色为重点红 `#C43D32`、风险琥珀 `#D08A18`、优化青绿 `#2C8C7A`、常规绿 `#3E7C56`。正文使用苹方/思源黑体系统栈，数字使用等宽字体。

识别元素是一条贯穿趋势和明细的 0–100 RDHS 分档标尺，45、60、70 三个阈值始终使用相同位置和颜色。页面不用装饰性渐变、漂浮卡片或大面积营销式 Hero。

## 错误与安全

- 查询失败时展示最近有效报告，并在页面顶部标注数据状态。
- 上传接口要求 `Authorization: Bearer <RDHS_INGEST_TOKEN>`，并使用常量时间比较。
- 同一源哈希重复上传返回幂等成功，不产生新版本。
- 数据校验失败返回明确字段错误，并写入失败诊断；不提升当前版本。
- 同步器不把 Meegle 原始凭据或站点写入密钥写入报告文件、日志或仓库。

## 自动运行

- `scripts/sync-rdhs-snapshot.py`：每月 1 日生成上个完整月快照并上传。
- 提供 `scripts/install-launchd.sh`，在当前 Mac 安装月度用户级定时任务；内网 Linux 可直接使用文档中的 cron 表达式。
- 同步失败返回非零退出码并保留本地诊断目录。

## 验收标准

- 实时同步读取 Meegle CLI 产物并成功写入站点。
- 历史月份查询、当月缓存刷新和业务线/产品下钻可用。
- 月度平均 RDHS、覆盖率、四档分布和五项趋势与快照手工计算一致。
- 未度量产品纳入重点治理且不显示虚假分数，测试业务线和交付定制产品不进入报告。
- 异常小快照和非法上传不会覆盖当前报告。
- 桌面与移动端无文本重叠、横向溢出或不可操作控件。
- 单元测试、接口测试、构建、浏览器交互和部署后检查全部通过。
